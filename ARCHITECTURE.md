# AzureIoTPyGate architecture

## Diagnostic logger (round 4)

`src/agent/log.py` provides off/info/debug/trace, resolving agent `PYGATE_LOG_LEVEL` before config `logLevel`, then info. Launchers resolve their flag before config/default and propagate it. Context's fixed legacy events remain intact; diagnostics instrument transport, twin, methods, DPS, OTA and state saves without changing wire data or security decisions.

Events use `datetime.utcnow().isoformat() + "Z"`, level/component/event and escaped key=value pairs. A bounded producer queue and daemon writer isolate console/file I/O; saturation drops diagnostics. File errors never raise into callbacks. Fixed numbered overwrite slots cap storage without Windows rename/replace assumptions. Log paths are confined to the external artifact root with realpath checks.

Before either sink, recursive redaction replaces values of keys containing key/secret/token/password/pwd/sas/sig/signature/cert/pem/connectionstring/privatekey, case-insensitively. URL queries/fragments, PEM, credential-shaped strings and exception text are hidden. String/body caps are 256/4096 characters, with truncation markers; traversal and queue budgets bound work. Safe original JSON formatting is preserved for trace comparisons, but diagnostic copies alone are redacted. Worker output retains the existing redacted stream channel, never this file writer.

### 4.2 Device templates (D13)

A Forge *device template* is a JSON document `templates/{name}/{version}.json`: display name; **capabilities** — each `{displayName, name, type: telemetry|property|command, schema, unit?, semanticType?, writable?}` (telemetry = body fields; property = desired/reported pair; command = direct method with request/response schema); default tags; default payload script name; default dashboard. Versioned and publishable like in IoT Central; the twin schema in §3 and the telemetry in §4 are the *thermostat* template. ## 6. Device runtime (agent ⇄ payload)

Payload module contract (plain Python, one file):
```python
VERSION_INFO = {"name": "thermostat"}            # optional metadata
def on_start(ctx): ...                            # called once after load
def on_tick(ctx): ...                             # called by the agent every telemetryIntervalSec (agent owns the clock)
def on_desired(ctx, patch): ...                   # desired props changed
def on_stop(ctx): ...                             # before unload / swap
```
`ctx` API (the only surface a payload may rely on): `ctx.send_telemetry(body: dict, props: dict | None)`, `ctx.desired` (read-only dict), `ctx.report(patch: dict)`, `ctx.log(msg)`, `ctx.now()` (UTC ISO), `ctx.state` (dict persisted in `state.json`), `ctx.device_id`.
Artifact signing: the signed bytes are the **exact UTF-8 bytes of the script file** served at `payload.url` (no manifest wrapping, so nothing is re-serialised). `payload.sig` = hex of the ECDSA P-384/SHA-384 signature in IEEE P1363 format (96 bytes, r||s); `payload.sha256` = hex SHA-256 of the same bytes. Forge keeps the private key in `D:\Configurations\AzureIoTForge\keys` and generates it on first use; the device config carries only the **public key PEM** (`payloadPublicKeyPem` path). Device verification: `pysharp_signing.verify("ecdsa-p384-sha384", public_pem, data, bytes.fromhex(sig_hex))` (`bytes.fromhex` exists from PySharp preview.8; older builds need `binascii.unhexlify`). Key rotation = publish a new public key to devices before signing with the new private key (OPENPOINTS (historical Forge reference; current concerns: ROADMAP.md)). .NET `ECDsa.SignData(..., DSASignatureFormat.IeeeP1363FixedFieldConcatenation)` ⇄ device verifier interop is covered by PySharp's `SigningModuleTests`.
OTA algorithm: receive `desired.payload` → compare with running version → `downloading` → fetch → `verifying` (size, sha256, signature, `compile()` syntax check, required entry points present) → `staged` → `on_stop` old → load new → `on_start` → **probation**: next N ticks (default 10) must complete without exception, else unload new, reload last-known-good, report `rolledBack` with error. After probation: preserve the former `lastGood` in optional `previousGood`, write `lastGood`, report `running`. Old state files without `previousGood` remain readable. Explicit rollback restores the previous accepted descriptor (or lastGood while a candidate is in probation), returning failure if none exists. Automatic rollback still targets lastGood. Bootstrap returns `active`, `no_payload` or `failed`; a trusted local seed is copied and hash-checked before worker execution, while OTA artifacts also require signature verification. Failed restore/rollback clears executable payload references and reports failure through existing events/twin fields; transport and twin remain available but no synthetic telemetry is added. Never log or report secrets.

### Worker IPC recovery (2026-11-11)

`PayloadProcess` requires PySharp preview.10 or later, where Windows sharing violations are translated to `OSError`. It reads response files in the parent and retries locked, partial or invalid JSON until the callback deadline. Failed reads apply no state/effects. A complete response commits effects only once; recovery restarts the payload module with committed context state (module globals reset). Direct retry avoids the former disposable-reader process per callback, whose process churn correlated with unexplained `worker_exited` events in a concurrent soak.

Infrastructure faults (`worker_exited`, `watchdog_timeout`, `response_read_failure`) receive one fresh-worker recovery attempt. The replacement runs `on_start` and replays the full desired initialization before retrying the failed callback; initialization failure suppresses that retry. Two consecutive `on_tick` watchdog expirations, with successful replacement initialization, are classified as `payload_watchdog_timeout`, increment payloadErrors and roll probation back to lastGood. Exit/read failures remain infrastructure faults and preserve probation. Heartbeat timing is unchanged; healthy payloads require no recovery restart. Explicit payload error responses retain rollback. Bounded events and reported twin expose fixed reason codes, worker status and restart count. stdout/stderr capture is redacted and asynchronous, not an unredacted exception log.

Windows writer contention/partial JSON and actual worker kill recovery tested.
